# 과정(레슨) 작성 지침서

파이스쿨의 과정 하나는 `static/lessons/NN.js` 파일 하나입니다 (NN = 두 자리 번호, 예: `08.js`).
파일에는 아래 한 덩어리만 들어갑니다. 다른 파일은 건드리지 않습니다.

```js
LESSON_CONTENT[8] = {
  minutes: 25,                       // 예상 학습 시간(분). 8~45 사이 정수
  intro: "한두 문장의 소개 (20~150자)",
  goals: ["목표 1", "목표 2", "목표 3"],   // 정확히 3개, 각 60자 이내
  blocks: [ ...블록들... ],
};
```

## 1. 화면 구조: "한 화면 = 한 가지 설명"

- `{ t: "h", ... }` 블록이 **새 화면(섹션)의 시작**입니다. 다음 `h` 전까지의 블록이 그 화면의 내용이에요.
- 한 화면(모니터 한 장)에 들어가야 하므로 **글은 짧게, 한 화면에 개념 하나**만 다룹니다.
- 화면에서 글 블록(`p`, `list`, `steps`, `key`, `tip`, `warn`, `h3`)은 **왼쪽**, 그림·표·코드·편집기 등은 **오른쪽**에 놓입니다.
- 한 과정은 **화면(h) 9~14개**. 맨 앞은 개념 화면들, 끝에는 반드시 `QUIZ` 화면 1개와 `SUMMARY` 화면 1개를 둡니다 (그 뒤에 `refs`).
- 화면당 글 합계 **520자 이내**(최대 700자). 글 블록 4개 이내, 시각 자료 3개 이내, 편집기는 1개 이내.
- 개념 화면에는 반드시 시각 자료(코드+실행결과, 표, 카드, 그림 블록, 편집기 중 하나 이상)를 넣습니다.

### h 블록

```js
{ t: "h", text: "화면 제목", sub: "한 줄 요약", icon: "아이콘이름" }
{ t: "h", text: "확인 퀴즈", sub: "배운 내용을 점검해 봐요", icon: "circle-help", kicker: "QUIZ" }
{ t: "h", text: "오늘의 핵심 정리", sub: "이것만 기억해도 성공!", icon: "list-checks", kicker: "SUMMARY" }
{ t: "h", text: "...", sub: "...", icon: "...", wide: true }   // 표가 넓을 때: 글 위, 시각 자료 아래 한 줄로
```
`icon` 은 아래 **허용 아이콘** 중에서만 고릅니다 (없는 이름은 오류).

허용 아이콘: cpu, memory-stick, hard-drive, archive, folder, folder-open, file, file-code, file-text, image, file-spreadsheet, terminal, square-terminal, code-xml, globe, book-open, pen-line, settings, chart-column, bot, gamepad-2, lightbulb, triangle-alert, circle-check, search, puzzle, play, pencil, library, keyboard, download, arrow-right, check, brain, monitor, sparkles, message-square-more, graduation-cap, bookmark-check, chevron-down, arrow-left, rocket, trophy, mouse, clock, target, list-checks, save, folder-tree, route, files, wrench, command, power, circle-help, zap, folder-plus, rotate-ccw, hash, eye, copy, circle-x, layout-grid, workflow, list-todo, save-all, wand-sparkles, pointer

## 2. 글 안에서 쓰는 서식 (모든 문자열 공통)

| 쓰는 법 | 모양 | 언제 |
|---|---|---|
| `**굵게**` | 파란 굵은 글씨 | 용어, 중요한 말 |
| `==형광펜==` | 노란 형광펜 | **화면당 1~2곳만**, 가장 중요한 한 구절 |
| `` `코드` `` | 코드 글꼴 | 변수·함수·값·파일 이름 |
| `{{Ctrl+S}}` | 키보드 키 모양 | 단축키 (`{{Ctrl+Enter}}`, `{{Enter}}` 등) |

짝이 안 맞으면 오류입니다. **이모지는 절대 쓰지 않습니다.** HTML 태그도 쓰지 않습니다.

## 3. 블록 종류 (이 목록의 것만 사용)

### 글 계열 (왼쪽)
```js
{ t: "p", text: "문단" }
{ t: "list", items: ["항목", "항목"] }                 // 6개 이내
{ t: "steps", items: ["1단계", "2단계"] }              // 5개 이내, 번호가 붙음
{ t: "key",  text: "꼭 기억할 핵심 한 줄" }            // 초록 상자
{ t: "tip",  text: "알아두면 좋은 팁" }                // 노란 상자
{ t: "warn", text: "조심할 점" }                       // 빨간 상자
{ t: "h3",   text: "작은 제목" }
```

### 코드 (오른쪽) — 실행 결과까지 보여줌
```js
{ t: "code", file: "hello.py", py: true, text: 'print("안녕")', out: "안녕" }
{ t: "code", file: "터미널", text: "python hello.py", out: "안녕" }      // 셸 명령은 py 를 쓰지 않음
{ t: "compare", left: { file: "A", text: "..." }, right: { file: "B", text: "..." } }  // 코드 두 개 나란히
```
- **파이썬 코드는 반드시 `py: true`** 를 붙이고 `out`(실행 결과)을 정확히 적습니다. 검사기가 **진짜로 실행**해서 `out` 과 비교합니다. 틀리면 오류예요.
- `out` 은 마지막 줄바꿈과 줄 끝 공백만 무시하고 정확히 같아야 합니다. 여러 줄은 `"\n"` 으로 이어요.
- `input()` 을 쓰는 코드는 `stdin: "홍길동\n20"` 처럼 입력값을 주고, `out` 에는 **입력값이 화면에 그대로 한 번 더 찍힌 모양**을 적습니다 (터미널처럼: `이름: 홍길동`).
- 코드 줄은 가로 40자 안팎으로 짧게. 한 코드 블록은 12줄 이내.

### 직접 해보기 편집기 — **파이썬 과정의 핵심**
```js
{ t: "editor",
  title: "직접 해보기",                      // 선택
  task: "미션 설명. `print()` 로 ... 출력해 보세요.",   // 선택, 서식 사용 가능
  code: 'print("여기를 고쳐 보세요")',          // 시작 코드(필수)
  stdin: "홍길동\n20",                        // input() 에 넣을 값(input 을 쓰면 필수), 한 줄에 하나
  expect: "기대하는 출력",                     // 선택: 있으면 정답이에요! 확인을 해 줌
  solution: 'print("정답 코드")',              // expect 가 있으면 필수. 정답 예시가 접혀서 보임
  hint: "힌트 한두 문장" }                     // 선택
```
- 파이썬 과정(번호 7 이상)은 **편집기 4개 이상**. 절반 이상은 `expect`+`solution` 이 있는 **미션형**으로 만듭니다. 나머지는 코드를 고쳐 보며 결과를 눈으로 보는 **자유 실험형**(`expect` 없음).
- 시작 코드는 일부러 비워 두거나 `# 여기에 쓰세요` 주석만 둘 수 있어요. 미션형은 **정답이 하나로 정해지게**(출력이 딱 정해지게) 문제를 냅니다. 출력이 사람마다 다를 수 있는 열린 미션은 `expect` 를 쓰지 않습니다.
- 한 화면에 편집기는 **하나만**. 편집기 화면에는 설명 글을 짧게 두고, 코드 블록은 넣지 않거나 하나만 넣습니다.
- `solution` 은 검사기가 실제로 실행해서 `expect` 와 비교합니다.

### 표·카드·그림 블록
```js
{ t: "table", head: ["연산자", "뜻", "예"], rows: [["`+`", "더하기", "`1 + 2`"], ...] }   // 행 9개 이내, 칸 수는 head 와 같게
{ t: "cards", items: [{ icon: "globe", title: "제목", desc: "짧은 설명" }, ...] }          // 6개 이내, icon 은 허용 목록
{ t: "anat", parts: [{ code: 'print', label: "함수 이름", sub: "출력해줘!" }, { code: '"안녕"', label: "문자열", sub: "따옴표로 감싼 글자", hl: true }] }  // 코드 한 줄을 조각내 설명
{ t: "tree", items: [{ depth: 0, name: "폴더", note: "설명" }, { depth: 1, name: "a.py", type: "file", hl: true }] }  // 폴더 구조
{ t: "boxes", items: [{ name: "age", value: "25", type: "int" }, { name: "name", value: "'철수'", type: "str" }], cap: "변수는 값을 담은 이름표 붙은 상자" }  // 변수/리스트 값 상자 그림
{ t: "flow", items: ["시작", { t: "점수 ≥ 60 ?", k: "ask" }, "합격 출력", { t: "끝", k: "end" }] }                  // 순서/흐름 그림 (k: "ask"=판단 칸, "end"=끝 칸)
```
- `boxes` 의 `value` 는 문자열로 적습니다 (문자열 값은 따옴표까지: `"'철수'"`).
- `flow` 는 5~7칸 이내. 칸 글자는 짧게.
- 그림이 도움이 되는 개념(변수, 리스트 인덱스, 반복, 조건 분기, 함수 호출, 클라이언트-서버 등)에는 `boxes`/`flow`/`table`/`anat`/`tree`/`cards` 를 적극 사용합니다. **SVG(`fig`)는 쓰지 않습니다.**

### 퀴즈
```js
{ t: "quiz", q: "질문", options: ["보기 1", "보기 2", "보기 3"], answer: 1, explain: "해설(왜 그런지)" }
```
QUIZ 화면은 **3~4문제**, 보기 3~4개, `answer` 는 0부터 시작하는 정답 번호, **해설 필수**. 정답 번호가 항상 같은 자리에 오지 않게 섞어요.

### 참고자료 (맨 끝)
```js
{ t: "refs", items: [{ title: "...", url: "https://...", desc: "한 줄 설명" }] }
```
**주소는 `tools/allowed-links.json` 에 있는 것만** 쓸 수 있어요 (직접 열리는 것을 확인한 주소만 모아 둠). 없는 주소를 지어내면 오류입니다. 2~4개.

## 4. 글쓰기 원칙

- 독자: **프로그래밍을 처음 보는 사람**. 중학생도 따라올 수 있게. 용어는 처음 나올 때 쉬운 말과 비유로 풀어 줍니다.
- 문체: 자연스러운 **~해요 체**. 짧은 문장. "~하십시오" 같은 딱딱한 표현 금지.
- 비유를 적극 사용 (변수=이름표 붙은 상자, 리스트=번호 붙은 서랍, 함수=레시피 등).
- 한 화면 = 개념 하나 + 예시 하나. 어려운 개념은 두 화면으로 쪼갭니다.
- 화면 흐름: ① 왜 필요한가/무엇인가 → ② 가장 쉬운 예 → ③ 규칙 → ④ 자주 하는 실수 → ⑤ 직접 해보기 → ⑥ 퀴즈 → ⑦ 정리.
- 과장·낚시 표현, 확인 안 된 사실 금지. 정확한 내용만. 버전에 따라 달라지는 내용은 피합니다.
- 다른 과정의 내용을 가리킬 때는 "과정 8" 처럼 번호로 (아래 과정 지도 참고).

## 5. 파이썬 코드 규칙 (실행 결과가 늘 같아야 함)

- 파이썬 3.12 기준, **표준 기능만** (외부 패키지 금지).
- `random`, `time`, `datetime.now`, `input` 없는 임의 값 등 **실행할 때마다 달라지는 것 금지**. 날짜가 필요하면 날짜를 직접 적어요.
- **문자열 집합(set)을 그대로 출력하지 않습니다** (순서가 매번 달라짐). 숫자 집합이거나 `sorted(...)` 로 정렬해서 출력해요.
- `id()`, 메모리 주소, 파일 경로, 사용자 이름 같은 환경 의존 값 금지.
- 에러를 보여 줄 때는 **`out` 에 전체 Traceback 을 넣지 말고**, `try/except` 로 잡아서 `ZeroDivisionError: division by zero` 같은 **마지막 한 줄**만 출력하게 만듭니다. (에러가 나는 코드를 `py:true` 로 쓰면 실패 처리돼요.)
- 파일 입출력은 **17번 과정에서만** 사용. 파일은 브라우저 안의 가상 폴더에 만들어지므로 상대 경로(`memo.txt`)만 써요. 한글 파일은 `encoding="utf-8"` 를 붙입니다.
- 들여쓰기는 공백 4칸. 변수·함수 이름은 영어, 출력 글자는 한국어 가능.
- 코드 안 주석은 한국어로 짧게.
